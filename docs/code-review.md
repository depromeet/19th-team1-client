# 코드 리뷰 가이드

## 리뷰어

- 코멘트 머리말: `[필수]` 병합 전 꼭 고칠 것 / `[제안]` 작성자가 판단 / `[질문]` 이해 확인. 머리말이 없으면 `[제안]`
- resolve 는 리뷰어가 누른다. 답글과 반영 커밋을 확인한 뒤

## 작성자

- 리뷰 반영은 로컬에서 고쳐 커밋한다. suggestion 버튼은 쓰지 않는다 (커밋 훅을 건너뛰고 스레드가 자동으로 닫힘)
- 스레드마다 답글: 반영한 커밋 링크, 또는 반영하지 않는 이유
- 스레드를 직접 닫지 않는다. 예외: 봇(CodeRabbit 등) 코멘트는 처리한 뒤 직접 닫는다
- 리뷰어 답이 없으면 멘션해서 요청한다
- resolve 안 된 스레드가 있으면 병합되지 않는다

## AI 리뷰 (시범 운영)

- CodeRabbit 이 `dev` 대상 PR 을 자동 리뷰한다. `⚠️ Potential issue` 는 대응하고 나머지는 선택
- 1~2주 써 보고 계속 쓸지 정한다

## PR 제목

- 병합 커밋 제목이 된다 → 커밋 규칙대로 쓴다 (CI 가 검사). 예) `feat(web): 저장물 카드 목록 추가`
- 배포 PR(`dev` → `main`)은 `release: <배포 내용>`
