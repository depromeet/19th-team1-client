# 코드 리뷰 가이드

## 리뷰어

- 코멘트 머리말: `[필수]` 병합 전 꼭 고칠 것 / `[제안]` 작성자가 판단 / `[질문]` 이해 확인. 머리말이 없으면 `[제안]`
- resolve 는 리뷰어가 누른다. 답글과 반영 커밋을 확인한 뒤

## 작성자

- 리뷰 반영은 로컬에서 고쳐 커밋한다. suggestion 버튼은 쓰지 않는다 (커밋 훅을 건너뛰고 스레드가 자동으로 닫힘)
- 스레드마다 답글. 첫 단어는 `반영:`(커밋 링크) · `반영 안 함:`(이유) · `보류:`(언제 · 이슈) 중 하나 — 주마다 이 단어로 사례를 모아 기준을 고친다. `review-respond` 스킬이 초안을 쓴다
- 스레드를 직접 닫지 않는다. 예외: AI 리뷰 봇 코멘트는 처리한 뒤 직접 닫는다
- 리뷰어 답이 없으면 멘션해서 요청한다
- resolve 안 된 스레드가 있으면 병합되지 않는다

## AI 리뷰

- PR 을 `dev` 로 열면 Claude 가 먼저 리뷰한다. 커밋을 더 올리면 그 커밋분만 다시 본다 — `docs/decisions/0005-ai-review-claude.md`.
- 지시문은 `.github/claude-review.md`. 머리말(`[필수]` · `[제안]` · `[질문]`) + 종류: 장부 위반은 `C-xx`, 장부에 없는 결함은 `[결함]`(예시 입력이 근거).
- Claude 지적이 틀렸으면 `반영 안 함:` 에 왜 틀렸는지 한 줄 — 그게 리뷰어를 고치는 사례가 된다.
- 기준 관리자(@sikkzz)가 주 1회 스레드를 모아 기준을 고친다 — `docs/code-standards.md` "기준이 쌓이는 길".
- Claude 지적도 사람 지적과 같이 스레드마다 답한다. 처리한 뒤 작성자가 직접 닫는다(봇 스레드 예외).
- 리뷰마다 비용이 PR 댓글 "Claude 리뷰 비용"에 한 줄씩 쌓인다.
- PR 을 올리기 전에 같은 지시문으로 로컬에서 먼저 돌려 보면 PR 에서 지적·재리뷰가 줄어든다.
- `@coderabbitai` 는 부르지 않는다(`.coderabbit.yaml` 은 끄는 설정만 둔다).

## PR 제목

- 병합 커밋 제목이 된다 → 커밋 규칙대로 쓴다 (CI 가 검사). 예) `feat(web): 저장물 카드 목록 추가`
- 배포 PR(`dev` → `main`)은 `release: <배포 내용>`
