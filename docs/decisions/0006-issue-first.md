# 0006 작업은 이슈에서 시작한다

- 상태: 제안
- 날짜: 2026-11-26
- 정한 곳: PR #4

## 정한 것

PR 로 끝나는 작업은 이슈 → 작업 → PR → `dev` 병합 때 이슈가 저절로 닫히는 흐름으로 한다.

- 에이전트는 작업을 요청받으면 "이슈 만들어"라고 하지 않아도 `issue` 스킬로 이슈부터 만든다. 같은 작업의 열린 이슈가 있으면 그것을 쓴다. 질문·조사, 열린 PR 의 리뷰 반영·`rebase-dev`, 배포 PR 은 빼고, 사람이 이슈 번호를 주면 그 번호를 쓴다.
- 이슈는 `.github/ISSUE_TEMPLATE` 의 양식(버그는 `fix`, 그 밖은 `feat`)의 칸 그대로 쓰고, 라벨은 작업 브랜치의 type 과 같게 단다.
- `dev` 로 가는 PR 은 본문 "관련 이슈" 칸에 `close #번호` 를 적는다. CI(`pr-title.yml` 의 "관련 이슈")가 없으면 막는다 — 사람이 올리는 PR 에도 걸린다.

## 왜

- 이슈 · PR 템플릿은 있었지만 에이전트가 이슈를 쓰는 절차가 없어, 이슈가 하나도 없이 PR 만 쌓였다(PR #1~#4).
- 기본 브랜치가 `dev` 라 `close #번호` 가 있으면 병합 때 이슈가 닫힌다 — 할 일 목록이 저절로 맞는다.
- 글(`AGENTS.md`)과 스킬만으로는 빠뜨릴 수 있어 CI 로도 막는다.

## 버린 안

- 에이전트만 강제(CI 없음) — 사람 PR 은 자유롭지만, 에이전트가 빠뜨려도 막을 곳이 없다.
- "이슈 만들어"라고 할 때만 — 지금까지와 같아 이슈가 생기지 않는다.

## 다시 열 조건

작은 수정까지 이슈를 만드는 것이 번거로워 PR 이 늦어지면, 예외(라벨 등)를 둘지 다시 정한다.

## 알아 둘 것

- 다른 PR 위에 쌓은 PR 은 앞 브랜치로 병합되면 이슈가 닫히지 않는다 — 앞 PR 이 병합된 뒤 `rebase-dev` 가 대상을 `dev` 로 바꾸고 병합한다.
- 이슈 양식은 `gh issue create` 가 칸을 채워 주지 않아, 스킬이 양식의 칸 제목을 `### 제목` 으로 그대로 쓴다.
