# 결정 기록

팀이 정한 것과 그 이유를 남긴다. 나중에 "왜 이렇게 했지?"가 나오면 여기서 찾고,
뒤집고 싶으면 먼저 그 기록의 **다시 열 조건**을 본다. 에이전트도 정해진 것을 바꾸기 전에 여기를 읽는다.

## 언제 쓰나

- 되돌리기 비싼 선택 — 라이브러리, 폴더 구조, API 방식, 브랜치 전략
- 여러 안을 비교해서 하나를 고른 것
- 코드 기준(`docs/code-standards.md`)에 넣기엔 한 번 정하면 끝나는 것

코드 한 줄의 모양은 여기가 아니라 코드 기준 장부에 둔다.

## 규칙

- 파일 하나에 결정 하나. 이름은 `NNNN-짧은-제목.md` (예: `0005-short-title.md`).
- 번호는 다시 쓰지 않는다. 뒤집으면 새 기록을 만들고, 옛 기록 상태를 `대체됨: NNNN` 으로 바꾼다. 옛 기록은 지우지 않는다.
- 회의·PR 에서 정했으면 그 링크를 적는다.

## 양식

```md
# NNNN 제목

- 상태: 제안 | 확정 | 대체됨: NNNN
- 날짜: YYYY-MM-DD
- 정한 곳: <회의록·PR 링크>

## 정한 것

한두 문장.

## 왜

이 결정을 하게 만든 사정.

## 버린 안

- 안 이름 — 버린 이유

## 다시 열 조건

이런 일이 생기면 다시 논의한다. (예: 팀원이 4명을 넘으면, 첫 배포를 하면)
```
