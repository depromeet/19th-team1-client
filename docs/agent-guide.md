# 에이전트 사용 가이드

Claude Code 와 Codex 로 이 레포를 작업할 때 무엇이 자동으로 걸리고, 처음에 무엇을 해야 하는지 정리한다.
에이전트가 읽는 정본은 루트 `AGENTS.md` 다.

## 한눈에 — 세 층

위로 갈수록 세게 걸린다. 같은 지적이 반복되면 아래에서 위로 올린다.

| 층             | 걸리는 방식         | 누구에게          | 무엇                                                            |
| -------------- | ------------------- | ----------------- | --------------------------------------------------------------- |
| 1. 기계        | 매번 막음           | 사람·Claude·Codex | ESLint, 커밋 훅(lint-staged·commitlint), CI, 워크플로 보안 검사 |
| 2. 에이전트 훅 | 그 순간 되돌려 보냄 | Claude·Codex      | 위험 명령 검사 · 수정 직후 린트 · 완료 관문                     |
| 3. 읽히는 것   | 대개 지켜짐         | Claude·Codex      | `AGENTS.md`, 경로별 룰, 스킬, 코드 기준 장부                    |

## 처음 한 번

### Claude Code

- 레포 루트에서 `claude` 를 실행한다. 설정(`.claude/settings.json`)·룰·스킬이 자동으로 잡힌다.
- 처음 열면 이 폴더를 신뢰할지 묻는다 — 신뢰해야 훅이 돈다.
- 확인: 새 세션에서 `/hooks` 로 훅 3개(PreToolUse · PostToolUse · Stop), 스킬 목록에 `self-review` 등이 보이면 된다.

### Codex

- 레포 루트에서 `codex` 를 실행한다. 프로젝트를 **신뢰(trust)** 로 둬야 `.codex/` 를 읽는다.
- `/hooks` 에서 훅을 **승인**한다. 훅 파일이 바뀌면 다시 승인해야 돈다 (PR 로 훅이 바뀌었다는 공지가 오면 다시 승인).
- 스킬은 `.agents/skills/` 에서 읽는다.
- 확인: `codex execpolicy check --pretty --rules .codex/rules/team.rules git push origin dev` 결과가 `prompt` 면 묻기 규칙이 잡힌 것이다.

### Windows

`.claude/skills` 는 `.agents/skills` 를 가리키는 심볼릭 링크다. Windows 에서는 `git config core.symlinks true` 와 개발자 모드가 필요하다.
안 되면 알려 주세요 — 복사본 방식으로 바꾼다.

## 자동으로 걸리는 것

### 위험한 명령 (`scripts/agent-hooks/guard.mjs`)

| 처리 | 명령                                                                                          |
| ---- | --------------------------------------------------------------------------------------------- |
| 막음 | `.env`·키 파일을 셸로 읽기 · `--no-verify` · `HUSKY=0` · lease 없는 강제 푸시 · npm·yarn 설치 |
| 물음 | 푸시 · 패키지 추가·삭제 · `reset --hard` 등 되돌리기 · `pkill`·`killall` · 넓은 `rm -rf`      |

- 막힌 명령은 에이전트가 실행하지 않는다. 꼭 필요하면 사람이 터미널에서 직접 실행한다.
- 물음은 Claude 에서는 훅이, Codex 에서는 `.codex/rules/team.rules` 가 묻는다. Codex 쪽은 명령 앞부분으로만 맞춰서 `pnpm --filter … add` 처럼 중간에 옵션이 끼면 묻지 않는다 (알고 둔 빈틈).
- `.env` 파일은 Claude 의 파일 읽기 도구로도 열리지 않는다(`permissions.deny`). `.env.example` 은 열린다.

### 수정 직후 린트 (`post-edit.mjs`)

- 에이전트가 파일을 고치면 바로 Prettier 와 그 워크스페이스의 ESLint(`--fix`)를 돌린다.
- 자동으로 못 고친 오류는 에이전트에게 돌려보내 바로 고치게 한다.
- Codex 는 경로별 룰을 자동으로 읽지 않아서, 웹·앱·TS 파일을 처음 고칠 때 그 룰 본문을 넣어 준다.

### 완료 관문 (`stop-gate.mjs`)

- 이 세션에서 코드 파일을 고쳤는데 `self-review` 를 안 돌리고 끝내려 하면 **한 번** 돌려보낸다.
- 에이전트는 완료 검사를 돌리거나, 필요 없으면 `검사 생략: <사유>` 를 적고 끝낸다. 같은 변경에서는 다시 막지 않는다.
- 문서·설정만 바꾼 작업은 걸리지 않는다. 셸 명령으로 쓴 파일은 보지 못한다(수정 도구로 고친 것만 본다).

훅 상태는 `.git/agent-hooks/` 에 남는다 — 커밋되지 않고 지워도 된다.

## 자주 쓰는 요청

| 이렇게 말하면              | 스킬             | 하는 일                                                             |
| -------------------------- | ---------------- | ------------------------------------------------------------------- |
| "검사해" / 작업 끝         | `self-review`    | 변경 크기 판정 → 검사 → 기준 대조 → 결과 표                         |
| "커밋해"                   | `commit`         | 이번 작업 파일만 관심사별로 커밋                                    |
| "PR 올려"                  | `pr`             | dev 에 맞추기 → 푸시 → 템플릿 채워 PR → `@coderabbitai review` 댓글 |
| "dev 에 맞춰" / 앞 PR 병합 | `sync`           | rebase (앞 PR Squash 병합이면 `--onto`)                             |
| "리뷰 반영해"              | `review-respond` | 스레드 분류표 → 고른 것만 반영 → 답글 초안 (게시는 사람이)          |
| "기준에 넣어"              | `add-standard`   | 장부에 번호로 올림, 이미 있으면 다음 단계 제안                      |

## 코드 기준 장부

`docs/code-standards.md` — 지금은 전부 **초안**이다. 이 PR 리뷰에서 항목마다 동의·반대를 달아 주세요.
리뷰 코멘트에서 번호로 인용하면(`C-17`) 에이전트도 같은 번호로 찾아 고친다.
같은 지적이 두 번 나오면 장부에 올리고, 그래도 반복되면 룰 → 기계로 올린다.

## 훅·스킬을 고칠 때

- 훅을 고치면 `pnpm test:hooks` 로 시험한다. 걸려야 하는 입력과 걸리면 안 되는 입력을 짝으로 더한다.
- 스킬은 `.agents/skills/` 만 고친다 (`.claude/skills` 는 링크).
- 훅을 바꾼 PR 은 Codex 사용자에게 다시 승인해야 한다고 알린다.
