# dev 배포 확인

| 무엇         | 주소                                                         |
| ------------ | ------------------------------------------------------------ |
| `dev` 브랜치 | https://19th-team1-client-git-dev-sik02s-projects.vercel.app |
| PR 미리보기  | PR 에 Vercel 이 다는 댓글·검사의 주소                        |

1. **배포가 끝났나** — 확인할 커밋의 Vercel 배포가 성공했는지 본다.
   ```bash
   gh pr checks <번호>                                    # PR 미리보기 — Vercel 줄
   gh api repos/depromeet/19th-team1-client/commits/<커밋>/status \
     -q '.statuses[] | select(.context | test("Vercel")) | .state + " " + .target_url'   # dev 에 병합된 커밋
   ```
   빌드가 실패했으면 Vercel 로그 주소를 보고하고 멈춘다(로그는 Vercel 프로젝트 관리자만 본다).
2. **무엇을 볼지** — 확인할 PR 본문의 "확인 방법" 칸을 그대로 하나씩 따라 한다(`gh pr view <번호> --json body`). 칸이 비었으면 그 PR 의 바뀐 화면·경로. 화면이 안 바뀐 변경이면 첫 화면이 뜨는지만 본다.
3. **열어 보기** — 브라우저 도구로 **휴대폰(390) · 데스크톱(1280)** 두 크기.
   - 먼저 API 요청이 dev 서버로 가는지 본다(네트워크 탭의 주소).
   - 바뀐 영역 · 그 영역을 쓰는 동작 하나를 결과 화면까지 · 콘솔 에러 · 실패한 네트워크 요청(특히 API 주소·CORS).
   - 로컬에서는 됐는데 여기서 안 되면 환경 차이부터 본다: Vercel 환경 변수(`NEXT_PUBLIC_*`), 서버의 CORS 허용 주소, 서버 쪽 데이터.
   - dev 데이터는 팀이 같이 쓴다. 확인하려고 데이터를 만들거나 지웠으면 보고에 적는다.
4. **보고** — 본 주소·커밋, 크기별로 본 것, 콘솔·네트워크 에러, 로컬과 다른 점. 사진을 찍었으면 직접 열어 본 뒤 싣는다.
