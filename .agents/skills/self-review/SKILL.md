# 완료 검사

목적은 사람이 고쳐 주는 시간을 줄이는 것이다. 걸린 것은 보고하기 전에 스스로 고친다.
고칠 수 없거나 기준이 이 경우에 안 맞으면 숨기지 말고 번호와 이유를 적는다.

## 1. 변경 크기 — 스크립트가 정한다

```bash
node scripts/change-tier.mjs
```

나온 **해야 하는 것은 전부 하고, 하지 않는 것은 하지 않는다.** "작은 수정이라서"로 줄이지도, "혹시 몰라서"로 늘리지도 않는다.
사람이 이번에 빼라고 한 것만 예외이고, 그 말을 보고에 옮긴다.

| 크기        | 무엇                                           | 핵심                                                |
| ----------- | ---------------------------------------------- | --------------------------------------------------- |
| 문서·설정만 | 코드 파일이 안 바뀜                            | 링크·예시 명령 확인만                               |
| 코드        | 코드는 바뀌고 화면 파일은 안 바뀜              | 그 워크스페이스 타입·린트 + 관련 테스트 + 기준 대조 |
| 화면 수정   | 있는 화면 파일을 고침                          | 위 + 빌드 + 바뀐 화면 직접 확인                     |
| 새 화면     | 새 `page.tsx` 가 생겼거나 화면 변경 150줄 초과 | 위 + 전체 흐름 확인 + 디자인과 다른 점              |

목록에 이번 작업이 아닌 파일(다른 세션의 변경, 생성물)이 섞였으면 빼고 다시 판단하고, 그 이유를 보고에 적는다.
실패한 검사는 고친 뒤 **실패한 것만** 다시 돌린다.

## 2. 코드 기준 대조

`docs/code-standards.md` 를 통째로 읽지 않는다. 바뀐 파일 종류에 맞는 번호만 찾아 읽는다.

| 바뀐 파일                | 대조할 번호                                                                       |
| ------------------------ | --------------------------------------------------------------------------------- |
| 모든 `.ts` · `.tsx`      | C-04 · C-05 · C-06 · C-10 · C-11                                                  |
| 화면 `*.tsx` (웹 `src/`) | C-13 · C-14 · C-15 · C-16 · C-17 · C-18 · C-19 · C-20 · C-21 · C-22 · C-30 · C-31 |
| 쿼리·뮤테이션 훅         | C-23 · C-24 · C-25 · C-26 · C-27                                                  |
| 순수 함수 · `utils.ts`   | C-07 · C-08                                                                       |
| 권한·소유권이 걸린 분기  | C-28                                                                              |
| `*.test.*` · `e2e/**`    | C-33 · C-34 · C-35 · C-36 · C-37                                                  |
| 새 화면                  | C-29                                                                              |

- **이번에 새로 쓰거나 고친 줄만** 판정한다. 기존 줄의 어긋남은 고치지 않고 `기존` 이라고만 적는다.
- 파일을 실제로 열어 보고 판정한다. 기억으로 판정하지 않는다.
- 기계(ESLint)가 막는 번호(C-01 · C-02 · C-03 · C-09 · C-12 · C-32)는 린트 통과로 갈음한다.
- 해당 없는 번호는 판정하지도 적지도 않는다.

## 3. 요청 대조

이번 요청을 다시 읽고:

- 요청한 항목마다 `됨` · `안 됨(이유)` · `일부(무엇이 남음)`
- 요청에 없는데 한 것: 0 이어야 한다. 있으면 되돌리거나 꼭 필요했던 이유를 적는다.
- 받은 내용(요청·디자인·API 문서)에 없는데 지어낸 값·문구·필드: 0 이어야 한다.

## 4. 화면 확인 — 크기가 화면 수정·새 화면일 때

- 바뀐 경로를 브라우저로 열어 본다. 바뀐 영역과 그 영역을 쓰는 동작 하나로 좁힌다.
- 브라우저 도구가 없으면 `화면 확인 필요: <무엇이 없어서>` 로 남긴다. "작은 수정이라서"는 사유가 아니다.

## 5. 보고

터미널에서 읽힌다. 걸린 것만 한 줄씩 쓰고, 단순히 지킨 것은 마지막 한 줄로 묶는다.
판정은 셋뿐이다: `✅ 지킴` · `🔧 어긋남 → 고침` · `⚠️ 어긋남 → 남김`. 애매하면 셋 중 하나로 정하고 이유를 쓴다.
번호만 쓰지 않고 `번호 + 기준 이름` 으로 쓴다. 초안 기준이면 `(초안)` 을 붙인다.

예:

**완료 검사 — 변경 크기: 화면 수정 · 기준 7개: 지킴 5 · 고침 1 · 남김 1**

| 기준                                   | 결과             | 내용                                                                            |
| -------------------------------------- | ---------------- | ------------------------------------------------------------------------------- |
| C-17 로딩·에러·빈 상태는 위에서 (초안) | 🔧 어긋남 → 고침 | `items ?? []` 를 위에서 끊는 방식으로 바꿈                                      |
| C-04 옵셔널은 최후 수단 (초안)         | ⚠️ 어긋남 → 남김 | `memo?` — 서버 계약에 필수 여부가 없음. 서버 확인 필요                          |
| 나머지 5개                             | ✅ 지킴          | 컴포넌트 하나·파일 이름 · useEffect 없음 · 중첩 삼항 없음 · cn() · 쿼리 키 함수 |

- 요구: 3개 중 3개 됨 · 요청에 없는데 한 것: 없음
- 검사: `typecheck ✅ · lint ✅ · vitest related 4개 ✅ · build ✅`
- 화면: `/items` 를 390 폭으로 확인 — 저장 실패 토스트까지
- 기준표 밖에서 고친 것: (있을 때만)

### "문제 없음"이라고 쓸 수 없는 경우

아래 중 하나라도 있으면 "완료"·"문제 없음"이라고 쓰지 않고, 무엇이 남았고 누가 정해야 하는지 쓴다.

- `⚠️ 어긋남 → 남김` 이 있다 — 남은 것은 PR 리뷰 포인트로 넘긴다
- 요청한 것 중 안 된 것이 있다
- 화면을 바꿨는데 사유 없이 확인하지 않았다

## 6. 기록

보고를 낸 뒤:

```bash
node scripts/change-tier.mjs --mark
```

다음 검사가 지금 뒤로 바뀐 것만 보게 하고, 완료 관문(stop-gate 훅)이 이 기록을 보고 통과시킨다.

## 7. 기준 후보

반복될 만한 지적이 있었거나 장부에 없는 판단을 했으면 보고 끝에 한 줄:
`기준 후보: "<한 문장>" — 장부에 넣을까요?` (`add-standard` 스킬로 이어진다). 작업 중간에는 묻지 않는다.
